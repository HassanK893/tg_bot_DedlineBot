# Правила работы в этом проекте

## Файлы окружения — только с разрешения

Файлы `.env` и любые их варианты (`.env.local`, `.env.production`, `.env.*`, а также `*.pem`, `*.key` и прочие файлы с секретами) — закрытая зона.

**Запрещено без явного разрешения владельца проекта в текущем диалоге:**

- читать содержимое `.env` любым способом — `Read`, `cat`, `Get-Content`, `type`, `grep` по значениям, чтение через скрипт или запуск кода, который печатает переменные;
- изменять, дописывать, перезаписывать или удалять `.env`;
- копировать `.env` в другое место, в том числе во временные папки;
- выводить значения переменных окружения в чат, в логи или в вывод команд.

**Разрешено без спроса:**

- проверять факт существования файла;
- получать список имён переменных без значений (например, `grep -o "^[A-Z_]*=" .env`);
- ссылаться на переменные по имени в коде (`process.env.BOT_TOKEN`).

**Как правильно поступать вместо этого.** Если для работы нужна новая переменная — не добавлять её в `.env` самостоятельно, а сказать владельцу проекта, какую строку вписать и куда. В коде и документации вместо реальных значений оставлять понятную заглушку (например, `BOT_TOKEN=токен`), чтобы владелец подставил секрет сам.

Разрешение действует только на конкретное действие и только в том диалоге, где оно дано. Согласие на одну операцию с `.env` не распространяется на следующие.
